# Extension Guide

## 새 모델 추가

새로운 제한 개념이 필요하면 `rate-limiter-core` 안에서 먼저 모델을 추가합니다.

- 모델은 가능한 한 작게 유지합니다.
- 판정에 필요한 입력은 `RateLimitKey`, `RateLimitPlan`, `RateLimitPolicy` 수준에서 유지합니다.
- 새 모델이 기존 의미와 충돌하지 않는지 테스트를 추가합니다.

## 새 SPI 추가

새로운 연동 포인트가 필요하면 `rate-limiter-spi` 안에서 인터페이스를 추가합니다.

- SPI는 외부 구현이 그대로 이해할 수 있어야 합니다.
- 반환 타입은 가능한 한 명확하게 유지합니다.
- 구현 세부사항이 SPI 이름에 들어가지 않도록 합니다.

## 권장 원칙

- 계약은 기술보다 먼저 정의합니다.
- 모델과 SPI를 한 곳에 섞지 않습니다.
- Spring이나 Redis 연동이 필요하면 별도 2계층에서 다룹니다.
